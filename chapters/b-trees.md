## 1. 为什么内存树不够

二叉树每个节点只有两个孩子，磁盘读取一个节点可能只利用很少数据。数据库不能为每一层都做一次随机磁盘读，还要控制树高和写放大。

B 树 / B+ 树把一个节点做成一页：一次 I/O 读入多个键。

## 2. B 树

一棵最小度数为 `t` 的 B 树：

- 每个节点最多 `2t - 1` 个键；
- 内部节点最多 `2t` 个孩子；
- 除根外至少 `t - 1` 个键；
- 所有叶子在同一层；
- 键把子树范围切开。

插入时若节点已满，先分裂：

```text
[x y z]        y
              / \
           [x]   [z]
```

分裂把中间键上移，保持所有叶子深度相同。

## 3. B+ 树

B+ 树与 B 树最大的差异：

- 内部节点通常只存索引键；
- 真实数据都在叶子；
- 叶子通常用链表连接；
- 范围扫描顺着叶子链走，不需要回溯。

这也是数据库索引常用 B+ 树的原因：

```text
范围查询 a <= key <= b:
1. 从根定位到叶子；
2. 在叶子内二分找起点；
3. 沿叶子链表顺序扫描；
4. 超过 b 停止。
```

## 4. 代价

| 操作 | B/B+ 树 | 说明 |
|---|---:|---|
| 查找 | O(log n) | 树高乘节点内查找 |
| 插入 | O(log n) | 可能触发分裂 |
| 删除 | O(log n) | 可能借键、合并 |
| 范围扫描 | O(log n + m) | m 是返回数量 |

节点越大，树高越低，但节点内查找、写放大和缓存开销也要平衡。

## 5. 陷阱

- B+ 树的叶子链表需要维护插入和分裂后的前后指针。
- 节点内可以用二分查找，不要线性扫描大页。
- 删除不一定要立刻收缩树高，过度合并会增加写放大。
- 数据库索引还涉及页大小、聚簇索引、二级索引、事务和缓存，不能只看理论复杂度。

> B+ 树不是更高级的二叉树，而是把“树高、磁盘页、顺序 I/O”一起设计出来的结构。
