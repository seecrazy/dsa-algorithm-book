## 1. 这本书解决什么问题

很多人学算法的困境不是“没看过答案”，而是答案看了就忘。原因通常是：只记住了代码形状，没有记住代码背后的决策链。本书把每个主题拆成五层：

1. **动机**：为什么会有这个结构？
2. **承诺**：它在哪些操作上省时间？
3. **不变量**：正确性靠什么维持？
4. **模板**：常见形状怎么写？
5. **陷阱**：什么样的问题会让人写崩？

## 2. 三遍学习法

### 第一遍：读直觉

不看题解代码，先回答：

- 输入规模在哪里？
- 我要维护什么状态？
- 每次决策能否安全丢弃一部分候选？

### 第二遍：写小例子

选规模为 0、1、2 的例子。小例子不是浪费时间，它们专门攻击空指针、越界、重复元素、并列最大值这些“小怪兽”。

### 第三遍：复述与迁移

合上书，用一句话说出：

```text
这类问题的核心状态是 ______；
转移/移动规则是 ______；
停止条件是 ______；
我通过 ______ 保证不漏解。
```

## 3. 题目怎么用

每道题都分成两层：

- **题面层**：先自己写暴力，确认理解约束。
- **解法层**：展开思路后，不要照抄，先复述复杂度和易错点。

建议用“红黄绿”标记：

- 绿：能独立写出且解释复杂度。
- 黄：有思路但边界写错。
- 红：完全没方向。

三天后只看黄题，一周后重看红题。

## 4. 代码约定

示例偏 Python，因为它接近伪代码，同时足够严格。学习时不必纠结语言细节，应关注：

- 函数输入和输出契约；
- 循环不变量；
- 是否会修改输入；
- 整数溢出、空集合、重复元素、负数边界。

## 5. 快速路线

| 目标 | 路线 |
|---|---|
| 零基础系统学习 | 第 1-9 章，按顺序 |
| 面试前 4 周 | 复杂度、数组、哈希、树、图、DP、题库 |
| 面试前 2 周 | 每章“陷阱清单” + 题库按主题刷 |
| 工程复习 | 并查集、堆、缓存、调试与面试手册 |

> 学习算法不是为了崇拜聪明解法，而是为了在压力下仍有一条可靠的思考路径。
